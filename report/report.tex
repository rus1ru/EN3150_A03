\begin{abstract}
We compare two custom convolutional networks on EuroSAT RGB under a matched, single-seed training protocol. Both models use the same split, normalization, augmentation, batch size, 40-epoch budget and optimizer settings. Model A achieves 95.48\% test accuracy with Adam and 95.95\% with momentum SGD. Model B achieves 96.69\% and 97.14\%, respectively, with 96,538 parameters, below the 100,000-parameter limit. Separate pretrained MobileNetV2 and EfficientNet-B0 reference experiments achieve 97.65\% and 97.85\%. Model B offers lower parameter storage and counted arithmetic than Model A, but the comparison concerns complete architectures, not convolution type alone. Single-seed results and prior test-set reuse limit generalization claims.
\end{abstract}
\section{Introduction}
Deploying an image classifier on limited hardware requires balancing accuracy, weight storage and computation. Standard convolutions jointly learn spatial and channel features, whereas depthwise-separable convolutions split these operations to reduce arithmetic and parameter cost \cite{mobilenet}. Pretrained lightweight networks provide an alternative: they reuse features learned on a larger dataset, but may still exceed a small custom network's storage budget.

This study compares a standard CNN (Model A), a custom depthwise CNN (Model B), and fine-tuned MobileNetV2 and EfficientNet-B0. We examine three questions: how the custom models respond to different optimizers, whether Model B meets the 100,000-parameter constraint without a large accuracy loss, and how its accuracy and theoretical cost compare with the pretrained references.

\section{Dataset and protocol}
EuroSAT provides satellite imagery for land-use and land-cover classification \cite{helber}. We use the official RGB release from Zenodo record 7711810: 27,000 RGB images, ten classes, native $64\times64$ resolution. The frozen class-stratified split contains 18,900 training, 4,050 validation and 4,050 test images, using seed 42. The split manifests are shared across models; verification found no overlapping image paths between partitions.

Classes are AnnualCrop, Forest, HerbaceousVegetation, Highway, Industrial, Pasture, PermanentCrop, Residential, River and SeaLake, in that order. Augmentation and normalization fitting use training data only. Metrics use the complete 4,050-image test split; confusion-matrix rows represent true classes and columns predicted classes. We report accuracy and macro precision/recall with zero-denominator scores set to zero. Checkpoints are chosen using validation loss for A/B/MobileNetV2, and validation accuracy for EfficientNet-B0.

\section{Architectures and parameter accounting}
\subsection{Model A: standard convolution}
Model A contains four $3\times3$ convolutions. Every convolution is followed by ReLU and $2\times2$ max pooling. Channel/spatial sizes are
$3\times64\times64\rightarrow32\times32\times32\rightarrow64\times16\times16\rightarrow96\times8\times8\rightarrow112\times4\times4$.
Global average pooling produces 112 features, followed by a $112\rightarrow192\rightarrow10$ classifier with ReLU between linear layers. Standard convolutions/max pooling are established CNN operations \cite{alexnet}; global pooling avoids a large flattened head \cite{nin}.

ReLU is a max-with-zero operation without exponentials. Pooling reduces activation sizes. Parameter storage is not peak runtime memory.

\subsection{Model B: custom depthwise network}
Model B combines depthwise/pointwise convolution \cite{mobilenet}, inverted residuals and linear projections \cite{sandler}, and squeeze-and-excitation channel gates \cite{hu}. It is a custom configuration trained from scratch, not a pretrained MobileNet or a claimed new operation. An RGB pointwise lift creates 24 channels before the first strided depthwise filter. Seven expanded bottlenecks use expansion ratio two, widths 24, 32, 32, 48, 48, 80, 80, and four residual additions. Two SE gates are used. A pointwise head produces 192 channels, followed by global average pooling, dropout 0.1 and ten logits. Batch normalization and ReLU6 are used; hard-sigmoid gates avoid an exponential at inference.
Framework profiling gives a total of \textbf{96,538 trainable parameters}, including normalization and attention parameters, below the 100,000 cap. A depthwise/pointwise pair without biases has $9C_{in}+C_{in}C_{out}$ weights; normalization, linear layers and SE weights must also be included.

\subsection{Pretrained references}
MobileNetV2 \cite{sandler} uses ImageNet weights, three classifier-head warmup epochs then full fine-tuning, for 20 total epochs. EfficientNet-B0 \cite{tan} replaces its classifier with ten outputs and fine-tunes all weights for ten epochs. Both retain $64\times64$ inputs and apply ImageNet normalization and training-only horizontal/vertical flips. These are reference recipes, not matched-budget architecture ablations.

\section{Training settings}
The controlled custom-model study uses seed 42, the frozen shared split and the RTX 4050 Laptop GPU with PyTorch 2.4.1+cu121. Both architectures are unchanged. Each is trained independently for 40 epochs per optimizer, with batch size 64, plain cross-entropy and FP32 arithmetic (AMP and TF32 disabled). Both use the same training-pixel mean/std normalization and independent horizontal and vertical flips with probability 0.5. Validation and test apply normalization only.

Both models use Adam at learning rate 0.001, plain SGD at 0.01, and SGD with momentum 0.9 at 0.01. Weight decay is zero; there is no scheduler, label smoothing or early stopping. Adam provides an adaptive-step baseline, while plain and momentum SGD expose the effect of gradient accumulation under fixed settings. These learning rates were fixed before this study, not selected by a learning-rate search. Equal settings do not guarantee each architecture's optimal performance.

Within each architecture, the three optimizers begin from identical initialization. Training shuffle and augmentation streams are reset for each recipe. All six runs finish before any test evaluation. Checkpoints are selected by minimum validation cross-entropy, then evaluated on the full test split. CuDNN deterministic settings reduce variation but do not guarantee bitwise GPU reproducibility.

The pretrained references are separate, unmatched experiments. MobileNetV2 uses 20 epochs, batch size 32, Adam with head learning rate 0.001 then 0.0001, and CPU execution. EfficientNet-B0 uses ten epochs, batch size 32, Adam at 0.0001, and CUDA execution. They are not part of the controlled A/B training comparison.

\section{Discussion}
Model B exceeds Model A by 1.21 percentage points with Adam, 9.56 points with plain SGD, and 1.19 points with momentum SGD. Momentum SGD improves on plain SGD by 12.44 points for Model A and 4.07 points for Model B. Momentum can accumulate consistent gradient directions, but these results apply to the fixed learning rates and one seed; they do not establish universal optimizer superiority.

Model B has approximately 50.6\% fewer parameters and 50.1\% fewer counted MACs than Model A. Its accuracy advantage persists under the matched training protocol. However, it also differs through batch normalization, residual additions, attention, dropout, activation functions and initialization. The experiment therefore compares complete architectures, not an isolated standard-to-depthwise replacement.

The separately trained MobileNetV2 and EfficientNet-B0 references score 97.65\% and 97.85\%. Model B with momentum SGD records 97.14\%, while using substantially fewer parameters. These reference scores provide context, not a matched-budget comparison or statistical ranking.

\subsection{Convergence and classification errors}
The largest directed off-diagonal counts in the displayed custom-model matrices are Model A momentum SGD: HerbaceousVegetation to PermanentCrop (17), PermanentCrop to HerbaceousVegetation (12), River to AnnualCrop (10). Model B Adam: PermanentCrop to HerbaceousVegetation (19), Industrial to Residential (11), Industrial to Highway (11). These identify observed errors; inspecting the images would be necessary to establish their visual causes.

Figures~\ref{fig:curves-a} and~\ref{fig:curves-b} show loss and accuracy histories for the controlled recipes. Both now use the same plain cross-entropy definition, although training augmentation and Model B's training-only dropout still affect training/validation differences. Figure~\ref{fig:confusion} displays Model A momentum SGD and Model B Adam, together with the pretrained references. All six custom-model results are reported in the table; the displayed matrices are illustrative, not a new test-based selection rule.

\subsection{Limitations}
The experiments use one seed and an image-level split, not a geographic holdout; spatially related satellite tiles can limit generalization. Earlier test scores were visible before architecture and epoch-budget changes. This adaptive test reuse means the results are exploratory rather than an untouched final assessment. An independent holdout and repeated seeds would be needed for stronger comparisons.

The custom models now share augmentation, normalization, optimizer settings, batch size, loss and epoch budget. Nevertheless, one fixed learning rate per optimizer and one seed cannot characterize optimal performance or uncertainty. Pretraining and different budgets distinguish the reference networks. Timing is also recipe- and hardware-dependent: MobileNetV2 ran on CPU, whereas the new custom runs and EfficientNet-B0 ran on CUDA. Parameter counts and MACs do not establish inference latency, energy use or peak runtime memory.

\section{Conclusion}
Under the recorded recipes, the custom sub-100k Model B attains accuracy close to the pretrained references while using substantially fewer parameters. Model B scores higher than Model A for each optimizer under the matched training protocol; repeat-seed studies are needed to assess the stability of these differences. Resource claims are restricted to parameter storage and explicitly counted operations; deployment speed and peak runtime memory remain unmeasured.
